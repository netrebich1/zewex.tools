# Заливка в Pinterest (Pin Uploader) — история, устройство, эксплуатация

Инструмент `uploader` (раздел Pinterest): автозаливка CSV-выгрузок пинов в Pinterest через профили Dolphin Anty.
Портал раздаёт задания и ведёт отметки в «Проектах», агент «Zewex Uploader» на ПК сотрудника открывает профили и заливает файлы.
Разработка: 2026-10-22 (план) → 2026-10-23 (портал + агент) → 2026-10-24 (установка с сервера, инструкция, автосопоставление,
наборы, автообновление, первый живой прогон) → с 2026-10-25 в ежедневной работе.

## Решения владельца

- Dolphin Anty у каждого сотрудника на своём ПК. Local API Dolphin отвечает только на `localhost:3001` той машины, где он открыт,
  поэтому «кликающая» часть живёт на ПК (агент), а портал — панель, очередь и CRM. Образец протокола — расширение Zewex Collector.
- Тариф Dolphin платный, один аккаунт-команда; токен Dolphin API один на всех, вводит администратор в портале, агент получает его в `hello`.
- 1 сайт = 1 аккаунт Pinterest = 1 профиль Dolphin. Правило для сотрудников: профиль в Dolphin называется доменом сайта.
- Запуск кнопкой и по расписанию агента; параллельность профилей — настройка (по умолчанию 1).
- Всё скачивается с нашего сервера (установщик Dolphin, ZIP агента), настройки только в интерфейсе портала; сотруднику не нужны Node, Claude и чьи-либо аккаунты.
- Проверка результата: «файл принят» + скриншот сразу; контрольный заход через 10 минут после цикла (см. «Известные проблемы»).
- Аналитика Pinterest — отдельный тип шага задания (`analytics`), следующий этап.

## Устройство

**Портал.** Страницы `src/app/(app)/pinterest/uploader/*`: Сегодня (таблица сайтов с файлом на день, запуск), Запуски (живая карточка с шагами агента,
ошибками, скриншотами), Сопоставление (сайт ↔ профиль, автопредложения, состояние аккаунта), Наборы (галочки сайтов для запуска и расписания),
Агенты (токены, параллельность, расписание, скачивание, токен Dolphin, если не задан), Настройки (токен Dolphin, «человечность», задержки проверки,
адрес массовой загрузки), Инструкция (ссылки на скачивание, шаги, слоты скриншотов — админ вставляет Ctrl+V).
Библиотеки `src/lib/uploader/*`: `types` (константы, виды ошибок), `agent` (протокол), `runs` (запуски, фазы, крон), `csv`, `views`, `match` (автосопоставление),
`sets`, `release` (сборки и ссылки), `sites`, `access`. Действия `src/actions/uploader.ts`. API `src/app/api/uploader/*`. Модели `Upl*` в `prisma/schema.prisma`.
Крон `uploaderTick` (`worker/cron.ts`, раз в минуту): агенты офлайн (2 мин без связи), просроченные аренды (10 мин, до 3 попыток), `VERIFY_WAIT` → задания проверки, расписание агентов.

**Протокол агента.** `POST /api/uploader/agent/{hello|profiles|next|progress|finish|fail|state}` с `Authorization: Bearer zxu_…` (в базе только sha256).
`hello` отдаёт токен Dolphin, «человечность», `bulkUrl`, `latest`/`latestUrl`; `profiles` принимает список профилей Dolphin (имя, теги, заметка тегом `note:`);
`next` выдаёт до `parallel` заданий; `progress` продлевает аренду и принимает скриншоты; `finish`/`fail` закрывают задание. CSV — `GET /api/uploader/file?task=`
(`buildTaskCsv`: та же логика, что ручная выгрузка `dayCsv`, но без события «скачано»).

**CRM.** Успех → `PrjUpload(source="auto")` с пометкой «авто · агент · N пинов · скриншот» и событие `export_uploaded`; сбой → `export_upload_failed`;
проверка → `export_verified`. Защита от двойной заливки: сайт с отметкой за день второй раз не заливается (ни по «Повторить неудачные», ни при выдаче задания).

**Агент** (`agent/uploader`, TypeScript, Node 22, playwright-core). Цикл: hello → профили (при старте и раз в час) → опрос заданий каждые 20 с → задание:
скачать CSV → `GET /v1.0/browser_profiles/{id}/start?automation=1` в Dolphin → `connectOverCDP` → главная Pinterest, пауза, прокрутка ленты → имя пользователя
со страницы настроек (сверка с `UplAccount.pinUsername`) → страница массовой загрузки → `setInputFiles` в поле CSV → ждать подтверждения → скриншот → закрыть
профиль → `finish`. Ошибки классифицируются (`src/errors.ts`, виды в `protocol.ts`); при `unknown`/`upload_form_changed` агент шлёт HTML страницы.
Файлы, журнал и конфиг (токен под DPAPI): `%LOCALAPPDATA%\ZewexUploader`. Окно состояния: http://127.0.0.1:47831/.
Сборка — на сервере при каждом деплое: `scripts/uploader/build-agent.sh` (dist + node_modules без dev + `node.exe` win-x64 + `ZewexUploader.cmd`) →
`storage/uploader/agent/zewex-uploader-<версия>.zip`, версия из `agent/uploader/package.json`, пересборка только при изменении `src`/версии; руками
`FORCE=1 bash scripts/uploader/build-agent.sh`. Автообновление (с 0.1.4): портал в каждом ответе шлёт `latest`/`latestUrl`; агент без заданий в работе
качает ZIP в `update/`, распаковывает (PowerShell Expand-Archive), пишет `pending.txt`, выходит кодом 75; `ZewexUploader.cmd` копирует файлы поверх
(кроме самого .cmd) и запускает заново. Установщик Dolphin: `storage/uploader/downloads/dolphin-anty-setup.exe` (`scripts/uploader/fetch-dolphin.sh`, официальный CDN).

## Pinterest: что проверено вживую (2026-10-24)

- Массовая загрузка: `https://www.pinterest.com/settings/bulk-create-pins/` (Settings → Import content → Bulk create Pins), блок «Upload .csv file».
  Файл уходит сразу после выбора; ответ: «Upload successful! Your file was uploaded and your Pins are being created. This usually takes about 2 hours.
  If there's an issue creating your Pins you'll be notified by email». Кнопка «Import» на той же странице относится к блоку TXT — не трогать.
- `/pin-creation-tool/` — создание одного пина с картинкой; CSV туда класть нельзя (ответ «Your upload failed because it's the wrong format»).
  Именно на этом упал первый прогон; адрес теперь в `UplSettings.bulkUrl`, селекторы — `agent/uploader/src/selectors.ts`.

## Известные проблемы и что дальше

1. **Фаза проверки ничего не читает.** На странице bulk-create-pins нет истории загрузок, все `verify.published = null`; Pinterest сообщает итог письмом.
   Варианты: найти страницу истории в Business Hub, или считать подтверждением «Upload successful» и заменить проверку на «пины появились в профиле».
2. **Сбои Dolphin при старте профиля:** `Operation timed out` (zentrosy.com 26–27.10), `E_PROXY_CHECK_ERROR` (woman-trend.com, thepinkgoose.com — прокси профиля),
   `Browser executable not found …\dolphin_anty\browser\1520\anty.exe` (beautydaily.com.ua — в Dolphin не скачано ядро браузера; классифицируется как
   profile_not_found, лучше отдельный вид `dolphin_browser_missing`). Все три — на стороне Dolphin/прокси, агент только сообщает.
3. **beautydaily.com.ua 25–26.10:** «после выбора файла Pinterest не показал ни подтверждения, ни ошибки за 90 с» — смотреть скриншот и HTML в карточке запуска.
4. Иконка в трее и запуск без .cmd (один exe) — не сделаны. Скриншоты в инструкцию не вставлены. Наборы сайтов пока не используются.
5. Следующий этап по плану — шаг `analytics`: снятие статистики из Pinterest Analytics в тот же визит.

## Эксплуатация

- Журналы: агент — `%LOCALAPPDATA%\ZewexUploader\logs\<дата>.log` на ПК сотрудника; портал — `journalctl -u zewex-tools`; запросы — `/var/www/zewex_tools_usr/data/logs/zewex.tools-frontend.access.log`.
- Состояние одной командой на сервере: tsx-скрипт с `prisma.uplAgent/uplProfile/uplAccount/uplRun/uplTask` (примеры в истории чата заливки) или таблицы `Upl*` в MariaDB.
- Аккаунт на паузе после отказа Pinterest (2 → 6 → 24 ч) снимается на «Сопоставлении» (статус «Работает»).
- Если сотрудник говорит «сделал», а в портале пусто — проверить базу и журнал запросов, прежде чем искать ошибку в коде.
