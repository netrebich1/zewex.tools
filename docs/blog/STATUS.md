# Pin Blog Article — состояние и история (на 2026-10-28)

Сервис инфо-статей под Pinterest в портале zewex.tools: раздел Pinterest → «Pin Blog Article», адрес `/pinterest/blog`,
проект ключей `blog`. Карта кода — `docs/blog/README.md`. Этот файл — что сделано, какие решения принял владелец,
где что лежит и что дальше. Читать первым при продолжении работы.

## Коротко

- Статья по ключу и теме: исследование → **тип статьи (формат)** → видео YouTube → план → реальные фото из Google Images →
  текст → (ИИ-картинка шагов) → вступление/FAQ → SEO-мета → плашки с текстом на фото → сборка и проверки → WordPress.
- Формат определяет система по **теме статьи** (заголовку). Сценарий (бывший «рецепт») = промты + модели + параметры.
- Цена статьи $0.03–0.10, время 5–40 мин (упирается в лимиты OpenRouter общего ключа).
- Ввод: списком («ключ | тема | фокус-ключ») или из **Google Таблицы** (формат ядер «Статей»), отчёт пишется обратно в таблицу.

## Конвейер (src/lib/blog/stages.ts, worker/blog/stages/*)

`research → scenario → video → outline → photo_search → photo_filter → photo_rate → photo_select → write → ai_images → wrap → meta → pin_images → assemble → publish`

| Этап | Что делает |
|---|---|
| research | бриф: интент, YMYL, факты, ошибки, вопросы; тема статьи от редактора передаётся в промт |
| scenario («Тип статьи») | формат по теме/ключу/интенту (`src/lib/blog/scenarios.ts`), надстройка YMYL; пишет итоговые параметры в снимок поста; отложенные форматы — стоп до расходов |
| video | YouTube (DataForSEO organic) по фразе из темы → фильтр (не shorts, 1.5–20 мин, ≥5k просм., встраивание по oEmbed) → субтитры топ-3 → оценка содержания ИИ + жёсткие правила (реклама, спонсоры, другая техника, опасно, кликбейт — нельзя); «по видео» — метод из видео в бриф |
| outline | план из каталога блоков (`blocks.ts`) + правила каркаса формата (`structure.ts`): число пунктов, фото у пунктов, группы большого списка, повтор при нехватке пунктов |
| photo_* | Google Images (DataForSEO, запас SerpApi) → тех. фильтр → vision-оценка (relevance/quality/**appeal**, «неприятный кадр», водяные знаки/коллажи/упаковка по описанию) → выбор (hero вертикальный; нет hero — любая ориентация; нет совсем — лучший кадр секции) |
| write | секции пачками по 4; запрет выдуманного опыта |
| ai_images | gpt-image-2: 2–4 панели без текста, номера 1..N и подписи канвой; только секции steps с ≥3 шагов; по умолчанию выключено |
| wrap | вступление, выводы, заключение, FAQ, дисклеймер; цифры = как в теле, без выдуманного опыта |
| meta | title/description/slug; число в H1 = реальное число пунктов |
| pin_images | плашка с заголовком над/под фото (как Canvas-пин, кадр целиком), шрифты/палитры пинов |
| assemble | HTML + JSON-LD (Article, FAQPage, HowTo или Recipe, VideoObject) + проверка качества + **проверка согласованности** (совет, не стоп; для списков не запускается) + самопочинка секций/обвязки |
| publish | WordPress: категория, фото в медиатеку (картинки с плашкой), запись, Yoast; отчёт в Google Таблицу |

## Форматы (типы статей) — `src/lib/blog/scenarios.ts`

Определяются по теме (первый подходящий): чеклист, большой список (до 400), тренировка, план по дням, рецепт (блюдо или DIY),
нумерованный список (до 50; число из темы, «How to X: 10 Tips», списки без числа «… Hacks/Tips/Foods»), инструкция по видео
(«how to» в теме), сравнение, объяснение, общая. Здоровье/деньги/безопасность (YMYL из брифа) — надстройка над любым форматом:
только исследование, без видео и ИИ-картинок, дисклеймер всегда. **Отложены** владельцем (2026-10-23, «потом отдельно»):
подборка рецептов и подборка идей с фото — `DEFERRED_SCENARIOS`, запуск и таблица их пропускают («формат пока не делаем»),
код каркаса `roundup` и ссылки «Get the recipe» оставлен. Проверка на 417 темах таблицы исследования: «общая» — 74 (18%,
почти все — отложенные подборки рецептов). Новый формат = запись в `SCENARIOS` + при необходимости блок в `blocks.ts`
и правила в `structure.ts`.

## Google Таблица — `src/lib/blog/sheets.ts`

- Подключение Google одно на портал (сервисный аккаунт в настройках сайта «Статей», блок «Google Таблицы»); низкоуровневые
  вызовы — экспорт из `src/lib/articles/sheets.ts`. Ссылка на таблицу — настройки сайта блога (`settings.sheetUrl`).
- Вкладка = домен сайта. Формат ядер (как у «Статей»): **Keyword = заголовок статьи (тема)**, **SEO Keyword = короткий ключ**,
  Focus Keyword; «Сценарий» и «Режим» допускаются и не используются. Альтернатива: Keyword = ключ + колонка «Тема статьи».
  По желанию «Год в URL». Гео/язык/свежесть фото не нужны (решение владельца: фото англоязычные, US).
- Берутся строки без «Статуса» и Publish URL. Портал пишет: «Тип статьи» (только точный заголовок — не трогает
  «Тип статьи в топ-10» исследования), «Статус» (в работе → черновик/опубликовано/ошибка), URL/Data Draft или Publish URL/Data Publish;
  недостающие колонки создаёт справа; досылка раз в 5 мин (`resyncBlogSheets`, worker/blog/index.ts).
- Запуск: «Новый запуск» → «Из Google Таблицы» → «Прочитать таблицу» (предпросмотр с ожидаемым типом) → «Запустить».
- Пример: таблица владельца `docs.google.com/spreadsheets/d/19b_c8amgPo1o76K8mm1mVYsaf1IKCNkNziBzRqhxyN8`, вкладка `lyntrico.com`
  (13 строк заполнены 2026-10-26, не запускались); CSV-шаблон `C:\focus-pomodoro\blog-examples\sheet-template\blog-sheet-sample.csv`.

## Параметры сценария по умолчанию (`DEFAULT_PARAMS`, сид `prisma/seed-data/blog/recipes.json`, seedRev 7)

900–1800 слов, 3–6 фото (hero вертикальный), голос блогера, тип статьи auto, основа «по видео», видео auto, ИИ-картинки off
(medium, до 2), плашки на всех фото в статье. Сид перезаписывает промты/параметры при смене seedRev.

## Решения владельца (хронология)

- 10-21: отдельный сервис; реальные фото из Google Images; структура и объём «от контекста»; эталоны women-lifstyle.com, woman-trend.com.
- 10-21: плашки с текстом на фото (как Canvas-пин, без обрезки); идея ИИ-картинки «по шагам».
- 10-22: неприятные фото недопустимы (кейс с отёком после краски); видео — опцией, **скриншоты из видео — нет** (много авторов).
- 10-22: по сравнению 6 стратегий — **«по видео» по умолчанию** для инструкций; типы статей система определяет сама.
- 10-22: **«рецепт» → «сценарий»** везде (Pin Blog Article и Pinterest Articles; Pins не трогали — там «рецепт» = дизайн Canvas).
- 10-23: формат по **теме статьи** (ключ + тема); подборки рецептов и идей — **отложить**.
- 10-26: загрузка/выгрузка через Google Таблицу как у «Статей», без гео/сценариев/режимов; таблица — в формате ядер.

## Как работаем (важно)

- Код `D:\Projects\zewex-tools`, ветка `add-claude-md` (не main). После правки: проверка → коммит **только своих файлов** → деплой → push.
  В дереве почти всегда есть чужие незакоммиченные правки других сессий: их не коммитить; `prisma/schema.prisma` — HEAD + свой кусок
  через `git hash-object` + `git update-index --cacheinfo`.
- Проверка: tar по ssh в `/root/zewex-check` (или полный rsync всего дерева), `npx prisma generate`, `tsc` ×2,
  `npx tsx scripts/blog/selftest.ts` (`BLOG_FONTS=/var/www/zewex_tools_usr/data/storage/pins/fonts`).
- Деплой `bash deploy/deploy.sh` (сам ждёт чужой деплой через flock). Правки только воркера можно выложить горячо: tar файлов в
  `/var/www/zewex_tools_usr/data/app`, chown `zewex_tools_usr`, `systemctl restart zewex-worker`.
- Скрипты на сервере: `.cjs` с `@prisma/client` в каталоге приложения или `npx tsx --env-file=.env x.ts`; после — удалить.
- Сервер `root@159.69.234.194`, ключ `~/.ssh/fastvps_ed25519`.
