# Один ключ на много сайтов: банк фото, разные подборки, дёшево (проект, не внедрено)

Запрос владельца 2026-10-15: один ключ пишется для разных сайтов, фото не должны совпадать; хранить кэш и неиспользованные
хорошие фото для других сайтов; менять выдачу для новых сайтов, сохраняя релевантность; цель — тысячи статей в день, недорого.

## Что есть сейчас (факты из базы на 2026-10-15 21:00 UTC)
- `ArtPhotoFingerprint` (sha256 + phash + URL, 30 дней): режим `uniqueMode=soft` — сначала свежие, потом с других сайтов, потом свои.
  Пока повторов почти нет (3 из 1 304 фото на 2 сайтах) — потому что ключи разные.
- Кэш поиска: тот же текст запроса → кандидаты из базы без запроса к API. Но оценка ИИ делается заново (платно), а запрос — точная строка.
- Кандидатов найдено 21 663: отбраковано 17 723 (82%). Из них фильтр (бесплатно, но это лишние поиски/скачивания) — 13 730:
  ориентация 2 170, мелкие ~2 000+, каталог, дубли. Оценка ИИ (платно) — 3 993, из них 139 «модель не оценила».
- Неиспользованные хорошие фото: 1 360 «reserve» + 121 «keep» — найдены, скачаны, оценены (оплачены) и пропадают.

## Решение в 4 шага (по убыванию эффекта на цену)

### 1. Фильтр размера и ориентации прямо в поиске (дёшево, сразу)
Google Images (через DataForSEO) умеет отдавать только крупные и вертикальные (`tbs=isz:l,iar:t` / параметры DataForSEO).
Сейчас треть кандидатов отсеивается потом как «мелкие/горизонтальные» → лишние доборы (4–9 поисков на статью).
Ожидание: меньше доборов и скачиваний; цена поиска на статью ↓ примерно на треть. Проверить на 20 ключах A/B.

### 2. Банк фото (переиспользование уже оплаченных оценок)
Новая таблица «фото-ассет»: URL, sha256, phash, размеры, домен, **не зависящие от ключа** признаки оценки ИИ
(водяной знак, ИИ-генерация, коллаж, качество, «Pinterest-привлекательность», описание кадра) + связь «ключ-кластер → фото»
с оценкой релевантности. Ключ-кластер = нормализованный ключ без года/шума («Purple Bob 2027» = «purple bob»), плюс синонимы.
- Новая статья по ключу K для сайта S сначала берёт из банка фото этого кластера, которые **не стояли на S** и стояли
  не более чем на N других сайтах (N=1–2) не позже X дней назад; доищет в интернете только недостающее.
- Оценка ИИ выполняется один раз на фото, а не на каждую статью: для банка — только дешёвая проверка «подходит ли к ключу»
  (если ключ тот же — вообще без неё). Это прямо бьёт по главной статье расходов (vision ≈ 58% цены статьи).
- Хранить только миниатюры (≈20 КБ) и метаданные; оригинал качать при публикации.

### 3. Разные подборки для разных сайтов из одного пула
Один поиск по ключу даёт 100–700 кадров. Вместо «первые N лучших — всем» пул делится между сайтами:
каждому сайту — свой непересекающийся срез (детерминированно по хэшу «фото+сайт»), лучшие кадры распределяются по кругу.
Так один поиск и одна оценка обслуживают несколько сайтов, а подборки не совпадают.
Если пула мало — разные формулировки поиска на сайт (детерминированный выбор шаблона запроса по сайту:
«… street style», «… close up», «… aesthetic», другой гео), страницы выдачи 2–3 (DataForSEO depth), но не случайный шум.

### 4. Правила уникальности (настройка, без кода позже)
- Внутри сайта — строго: фото не повторяется на одном сайте никогда (не 30 дней).
- Между сайтами — допускается редко: не больше 1–2 других сайтов и не в одной ленте по времени; «обложка» (первое фото) — только уникальная.
- Не зеркалить/не обрезать фото ради обхода проверки дублей — это обход правил платформ, не делаем.

## Цена (оценка, проверить на данных)
Сейчас фото-часть ≈ $0.06–0.09 на статью (норма 25–40). С фильтром в поиске и банком при повторных ключах:
поиск ↓ ~30%, оценка ИИ ↓ в разы для ключей, уже бывших в банке. Для тысяч статей в день с пересекающимися ключами
это основной рычаг; для уникальных ключей работает только шаг 1.

## Что наблюдать ночью/утром
- Сколько поисков на статью ПОСЛЕ правок (en, ×3) — costs.log.
- Доля «мелких/ориентации» в отсеве после смены гео/языка.
- Сколько «reserve/keep» остаётся неиспользованными на статью — потенциал банка.
