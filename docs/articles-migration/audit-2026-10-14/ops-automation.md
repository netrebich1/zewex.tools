# Автозапуск и ИИ-модерация фото — правки 2026-10-15

Просьбы владельца:
1. «Пауза 15 минут сбоила очень часто все процессы»: убрать автовыключение цепочек.
2. «Если я включаю режим модерации ИИ фото, то фотки должны модерироваться ИИ»: каждая статья сайта с включённой ИИ-модерацией проходит ИИ-проверку фото сразу, без пачек.
3. Понятный и честный экран «Автозапуск сайтов».

## 1. Автовыключение цепочек убрано

- Цепочки «Поиск фото» и «Написание» включает и выключает только владелец: переключатели сайта и мастер-выключатели. Сами они больше не выключаются и не включаются.
- `worker/articles/autostart.ts` теперь только разовая миграция. Старый код раз в минуту перезаписывал весь JSON настроек сайта и мог затереть то, что владелец только что сохранил в форме. Новый код срабатывает, только если на сайте остались старые поля:
  - включает обратно цепочку, выключенную простоем: `offReason = "idle"`, или без причины при старом `autoRestart ≠ false`. Выключенную вручную не трогает;
  - удаляет `autoRestart`, `*OffReason`, `*OffAt`, `*IdleSince`;
  - «Запуск от» ИИ-модерации, равный 20 (прежнее значение по умолчанию), меняет на 1;
  - пишет через `updateSiteSettings`: запись проходит, только если `updatedAt` не изменился, иначе повтор. Чужие изменения не теряются.
- Проверка на копии (только чтение, без записи): на всех трёх сайтах `autoRestart=true`. Их цепочки выключены простоем, миграция включит их обратно:
  - dailydishideas.com — фото и написание, «Запуск от» 20 → 1;
  - women-club.online — фото. «Запуск от» = 9 задал владелец, поэтому значение не трогаем;
  - beautydaily.com.ua — фото и написание, «Запуск от» 20 → 1.
- Опция «Автовключение» убрана из формы и с экрана. Старые данные читаются без ошибок, `mergeSiteSettings` устаревших полей не возвращает. Если API получит `autoRestart`, поле молча игнорируется.

## 2. ИИ-модерация фото: каждая статья, сразу

- `src/lib/articles/types.ts`:
  - новая функция `aiModerationOn(siteSettings, global?)`: ИИ-модерация включена на сайте **и** включён мастер-выключатель. Её же использует `worker/articles/runner.ts`: после `select` статья ждёт PHOTO_REVIEW;
  - `SITE_LIMITS` — общие пределы для формы и экрана: лимиты цепочек 1–50, «Параллельно» 1–50, «Запуск от» 1–200, «Ждать, если в публикации ≥» 0–1000;
  - по умолчанию `batchFrom = 1`.
- `src/lib/articles/launch.ts`: если ИИ-модерация сайта действует, у статей с реальными фото `photoReview = true` (колонка и снимок рецепта). Галочка запуска и колонка «Режим» таблицы при этом не важны. В карточке запуска модерация отмечена как «да». Статьи с ИИ-картинками не меняются: у них нет отбора фото, а `photoReview = true` выключило бы им модерацию готовой статьи.
- Форма запуска (`RunParamsFields`, `NewArticlesRunForm`): при включённой ИИ-модерации галочка «Модерация фото до текста» включена, заблокирована и подписана: «проверит ИИ». В настройках сайта она остаётся редактируемой: это значение по умолчанию на случай, если ИИ-модерацию выключат.
- `aiAutostartTick` (`src/lib/articles/aiModeration.ts`):
  - запуск ИИ начинается, как только ждёт хотя бы одна свободная статья без решения ИИ;
  - если у сайта уже идёт авто-запуск, новые статьи **добавляются** к нему: ставится `aiRunId`, растёт `total`, `concurrency` берётся из текущих настроек. Запуск идёт непрерывно;
  - если «Запуск от» > 1, ждём столько статей, но не дольше 30 минут;
  - `backlogThreshold` работает как раньше (0 — не ждать);
  - ручной запуск авто-запуску не мешает.
- Гонка «запуск завершился, а к нему как раз добавили статьи» закрыта с двух сторон:
  - `attachToRun`: если запуск уже не `running`, захват снимается;
  - `finishRunIfIdle`: после перехода в `done` снимаются непроверенные захваты, `total` уменьшается.
- `worker/articles/aiModeration.ts`: автозапуск ИИ работает на каждом проходе цикла, то есть раз в 20 с вместо 60 с.

## 3. Одни настройки в двух местах

- Форма настроек сайта и экран «Автозапуск сайтов» правят одни и те же поля с одинаковыми пределами. Раньше форма урезала лимиты до 20.
- Форма присылает рядом с каждым полем автозапуска и ИИ исходное значение (`orig_<имя>`). Сохраняются только поля, которые тронули в форме, остальные берутся свежими из базы. Так форма, открытая давно, не затрёт переключатели, изменённые на экране.
- `saveArtSiteSettings` и `patchSiteAutomation` пишут через `updateSiteSettings` со сравнением по `updatedAt`. Неизвестные поля JSON сохраняются.

## 4. Экран «Автозапуск сайтов»

- Колонка «Автовключение» и подписи «простой / вручную» убраны. В легенде и под таблицей сказано: «этапы сами не выключаются».
- Шаг 2 теперь «Проверка фото»: под числом указано, у кого статьи — «ИИ N · сотр. K».
- Группа «ИИ-проверка фото»:
  - колонки «Включена» («проверяет N · ждёт M» или «мастер выкл.»), «Параллельно», «Запуск от», «Ждать, если в публ. ≥»;
  - у мастер-выключателя есть подсказка, что он делает.
- «Что мешает сейчас»:
  - для цепочек: «выключено — включите переключатель», «занято X из Y»;
  - для ИИ: «ИИ проверяет фото: N», «Ждут ИИ: M — запуск в течение ~20 секунд», «ИИ ждёт K статей для запуска — поставьте „Запуск от“ 1», «ждёт: в публикации ≥ …», «включена на сайте, но выключена мастер-выключателем», «нет ключа „Зрение“ у владельца сайта», «Ждут сотрудника после ИИ: K».
- Разбивку считает `AiReviewBrief` (`checking + waiting + staff = review`) в `src/lib/articles/automation.ts`.

## Что не трогал (чужие файлы)

- `worker/cron.ts`: комментарий «автоотключение через 15 мин» устарел. Код рабочий: `autostartTick` по-прежнему возвращает `{enabled, disabled}`.
- `launchArticlesAction` (`src/actions/articles.ts`) при импорте из таблицы пишет `sheetUrl`, перезаписывая весь JSON настроек. Лучше перевести на `updateSiteSettings`.
- `/pinterest/articles/moderation/ai` (`aiRunsOverview`, `AiModerationPanel`) показывает `batchFrom` как есть.

- Чистые функции прогнаны на копии: миграция (повтор — no-op), `mergeSiteSettings`, `aiModerationOn`, `validateSitePatch`, диагностика.
- `ArtSite.updatedAt` — DATETIME(3), сравнение по миллисекундам работает.
