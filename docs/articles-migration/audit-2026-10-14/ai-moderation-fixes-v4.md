# ИИ-модерация фото (mix3.4): исправления по третьему кругу аудита

Правки по отчёту `ai-moderation-v3.md` (оценка 7,8/10, $0.0139 за статью) и поштучным вердиктам `ai-moderation-v3-audit.json`. **Не задеплоено**, воркер не перезапускался. Типы проверены в `/root/zewex-check`: `tsc` воркера без ошибок; в основном `tsc` 2 ошибки в чужом файле `scripts/pins/photo-score-test.ts` (правки другой сессии), в файлах модерации ошибок нет.

Файлы:
- `src/lib/articles/aiModerationRules.ts` — чистые правила: ничья по ИИ, сверх нормы, «расходятся», словарь ключа, выбор резерва для «крупно».
- `src/lib/articles/aiModeration.ts` — промты, порядок проходов (резерв порциями, «крупно» по резерву только для выбранных), сводка `version: "mix3.4"`.

## Что изменилось

### 1. Стоимость
- **Перепроверка «по аналогии» убрана.** За круг она отправила спору 90 оставленных фото и не убрала ни одного (~$0.0015 на статью). Спор теперь зовётся только при спорных фото. Список «уже убрано обеими моделями» остался текстом, картинками — 2 образца вместо 4.
- **Резерв в основных проходах — 10 кандидатов вместо 15** (`RESERVE_FIRST`). Если после спора норма не набирается, ещё 10 (`RESERVE_MORE`) уходят отдельным маленьким вызовом lite + flash только по новым кандидатам. Flash в этом вызове фото статьи не видит. Lite видит оставленные фото статьи как образцы, чтобы найти дубли. Битая миниатюра теперь заменяется следующим кандидатом, а не теряется.
- **«Крупно» по резерву — только для выбранных добавлений и 2 запасных** (`reserveZoomTargets`). Если кандидат с подписью отпал, берётся следующий; запасные уже просмотрены. Второй вызов делается, только если появилось непросмотренное добавление, не больше 2 вызовов. Добавляются только кадры, просмотренные «крупно». Если «крупно» упал, добавление идёт как раньше, без него.
- **Из прохода «крупно» убран вопрос про ИИ.** За круг он не сработал ни разу. Находки `ai` в ответах больше не учитываются.

### 2. Спор не отменяет сильную отметку «ИИ» в одиночку
- Сильная отметка (`strongAiFlag`): flash сказал `ai_fake` с оценкой ≤ 40 (`AI_TIE_MAX_SCORE`) или обе модели сказали `ai_fake`. Находки «крупно» сюда не входят.
- Если спор ответил «keep», это **ничья, и фото убирается** с причиной «спор оставил — ничья». Это касается и удалений «на подтверждение».
- Ничья считается удалением с одним сигналом. Поэтому при доле удалений больше 30% статья уходит людям. Если после ничьих норма не набрана, статья тоже уходит людям: «спорные ИИ-фото убраны (N), норма не набрана». Убранные кадры у людей помечены ✕, и их можно вернуть.
- В промт спора добавлено: оставить фото с отметкой ai_fake можно, только назвав признак настоящей съёмки (поры, случайный бытовой фон, естественные дефекты). Красивая ретушь и боке таким признаком не считаются.

### 3. Смысл ключа: слова не теряются
- Новые записи словаря: `almond`, `coffin`, `stiletto`, `square`/`squoval`, `oval` (формы ногтей), `short nails`, `long nails`, `bob`. Добавлены составные `french bob` и `french braid`: раньше «french bob» получал определение френча на ногтях.
- `knownVisual` склеивает все совпавшие записи. Значимые слова ключа без записи дописываются как `[also named] "white" — must be visibly true as named` (например, «white chrome nails»). Служебные слова в расчёт не идут (`KEYWORD_STOP`): nails, outfits, haircut, ideas, сезоны, годы. Сюда же входит `gel`, потому что гель на фото не отличить от лака.
- Примеры: «almond french nails» = [french] + [almond: заострённые бока, мягкая вершина; НЕ квадрат, овал, стилет]; «shag bob» = [shag] + [bob: длина от челюсти до плеч]; «short gel nails» = [short nails] без запроса к модели.
- Определение от модели проходит `completeVisual`. Пустое для ключа со значимыми словами не принимается: берутся буквальные слова ключа. Для «white sneakers outfits» это «"white", "sneakers" должны быть видны». Потерянные моделью цвет, материал, форма или длина дописываются через «ALSO». Если модель упала, тоже берутся буквальные слова. В промте определения запрещён пустой ответ, если в ключе есть цвет, материал, форма, длина или конкретная вещь. Кэш хранит сырой ответ, его версия (`v: 2`) не менялась, переоплаты нет.

### 4. Сверх нормы
- Сверх нормы по обычному порогу добавляется **не больше 1 фото** (`EXTRA_FREE`). Каждое следующее — только при оценке flash ≥ 90 (`EXTRA_STRONG_SCORE`) и «ок» от lite. Остальные условия прежние: порог по процентилю, lite «ок» без `dup_of`, предел +30%.
- Flash теперь отмечает похожие варианты полем `like` (тот же однотонный цвет и дизайн, не дубль). Кадр, похожий на уже выбранный, сверх нормы не берётся. При доборе до нормы он идёт после непохожих.

### 5. «Проверки сильно расходятся»
- Считаются только отмены, где за удаление была основная модель (`flashOverturned` / `flashFlags`, их ≥ 3, отменено больше половины). Отмены находок «крупно» и одиночных отметок lite не считаются.
- Промт «крупно»: сообщать только то, что нанесено на изображение (водяной знак, @ник, домен, подпись, логотип автора). Вывески магазинов и салонов, неон, витрины, постеры, бренды на одежде, сумках и товарах — никогда. В промте спора — то же.

### 6. Совместимость результата
- `removed`, `added`, `finalOrder`, `humanReasons`, `needed`, `overturned` — без изменений. Номера R1..Rn стабильны: досылка продолжает нумерацию (R11…), `resolveRef` берёт по индексу в общем резерве.
- `passCosts`: индексы 0–4 как в mix3.3 = [lite, flash, спор, смысл ключа, «крупно»]. В `[4]` теперь входит «крупно» и по статье, и по выбранному резерву. Добавлен `[5]` — досылка резерва (lite + flash), 0, если её не было.
- `review.v3`: убраны `recheck` и `consistency_drops`. Новые поля: `reserve_zoom`, `reserve_zoom_pass`, `reserve_zoom_error`, `reserve_more`, `reserve_more_pass`, `reserve_more_error`, `flash_flags`, `flash_overturned`, `tie_drops`. `passes` — фактическое число успешных вызовов. `review.audit` не трогается.
