# Расходы и ошибки сервиса «Статьи» — 2026-10-15

Просьба владельца: «отслеживание ошибок, детально, и учёт расходов по сайтам и прогонам отдельно».

## Как считаются расходы (src/lib/articles/costs.ts)

Одна функция `costBreakdown({ siteIds, siteId?, runId?, since?, until?, withArticles? })`. Права проверяет страница: расходы видны только при `seesTeamCosts(me)` (админ или право «Расход: команда/все»), список сайтов — из `artSiteWhere(me)`.

- **Источник — UsageLog** (refId = id статьи, проект `articles`): каждый платный вызов ИИ / DataForSEO / SerpAPI с точной ценой. `Article.costUsd` — та же сумма, поэтому итог сходится со статьями до копейки.
- **Фаза вызова определяется по времени**, а не по слоту (text_fast работает и в поиске, и в тексте):
  1. vision-вызов внутри окна ИИ-модерации статьи (`ArtAiModerationResult.createdAt…updatedAt`) → «ИИ-модерация»;
  2. иначе окно этапа воркера (`ArtStageLog.startedAt…finishedAt`; незакрытое окно — до следующего этапа, максимум час) → фаза этапа;
  3. иначе по слоту (ручные действия вне воркера): photo_dfs/photo_serp → поиск, text_main → текст, image_main → картинки, vision → ИИ-модерация (если у статьи были проверки ИИ) или оценка, остальное → «Вне этапов».
- Фазы: «Поиск фото» (search, filter), «Оценка фото» (rank, rate, select), «ИИ-модерация», «Картинки ИИ» (concept, images), «Текст» (plan…assemble, image_seo), «Публикация», «Вне этапов».
- **Почему не ArtAiModerationResult.costUsd и не ArtStageLog.costUsd.** Расход ИИ-модерации уже лежит в UsageLog (aiChat пишет refId = статья) — если прибавить `ArtAiModerationResult.costUsd`, он посчитается дважды. `ArtStageLog.costUsd` неполный: при временной ошибке этап закрывается без суммы.
- Без периода: весь расход статей + сверка с Σ `Article.costUsd` (`check`). С периодом: расход, сделанный в период (по времени вызова), — так «сайт по дням» честный.
- Исходы: опубликована (COMPLETED) / потеряно (FAILED, PUBLISH_ERROR, STOPPED) / в работе. «Одна опубликованная» — средний собственный расход опубликованной статьи; «Полная цена публикации» — весь расход / число опубликованных.

## Ошибки (src/lib/articles/errorsView.ts)

- `errorWhere(me, filter)` — видимость (как раньше: сайты пользователя или ошибки без сайта его команд) + фильтры сайт / запуск (через `article.runId`) / этап / период / состояние (открытые / устранённые / все) / сигнатура.
- `errorGroups` — группы по сигнатуре: сколько раз, открытых, впервые/последний раз, этап, сайты, свежий образец текста, понятное название и «что делать» (словарь `KNOWN_ERRORS` перенесён из журнала), затронутые статьи со ссылками, текущим статусом, этапом, числом ошибок и заметкой (`Article.note`), сколько сейчас в «Ошибке» и сколько всё-таки опубликовано.
- `retryGroups` — временные сбои: `ArtStageLog` status=error «Временная ошибка, повтор через …» (в ArtError не попадают), группы по этапу и тексту, статьи, ждущие повтора прямо сейчас (PENDING + note «Повтор этапа …»).
- `errorsSummary` — для виджетов.

Действия — новый файл `src/actions/articlesErrors.ts`: «Устранено», «Открыть снова», «Вернуть в работу». Работают в рамках того же фильтра (кнопка на странице запуска не трогает другие запуски). Старые действия в `actions/articlesModeration.ts` не менялись.

## Интерфейс

- **Журнал** (`journal/page.tsx`): период сутки / 7 / 30 / 90 / всё время.
  - «Ошибки»: фильтры запуск / этап / открытые-устранённые-все, сводка, «Горит сейчас», подробные группы с затронутыми статьями, блок «Временные сбои».
  - «Расходы»: KPI + полоса фаз, расход по дням (стек по фазам), матрица сайты × фазы с ИИ-модерацией (итог = общая сумма), запуски с расходами, сайты по дням.
  - «Вызовы ИИ» — без изменений, но сумма в описании скрыта без права на расходы.
- **Страница запуска**: карточка «Расходы запуска» (фазы, $ за опубликованную, полная цена, потеряно, сверка со статьями, таблица по статьям) и «Ошибки запуска» (группы + повторы, ссылка в журнал). Расход в строке прогресса теперь только при праве на расходы.
- **Сайт → Статистика**: период 7/30/90, расходы по фазам, по дням и по запускам; виджет ошибок (группы + повторы). KPI стоимости — только при праве на расходы.

## Замечания

- `ArticlesTable` (чужой файл) показывает цену статьи всем, без проверки права на расходы.
- Для очень больших периодов по всем сайтам `costBreakdown` читает все вызовы периода (сотни тысяч строк — несколько секунд); при росте объёма можно добавить индекс `UsageLog(projectId, createdAt)`.
